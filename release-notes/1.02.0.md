# Bolt 1.02.0

Bolt's Cockpit release brings a reviewed AnyKernel installation flow, recovery
bundles and readable kernel-provider logs to rooted Android devices.

## What's new

- Asgardian Cockpit with Overview, Recovery and Activity screens, adapted from
  Thor's colors and typography.
- System, Light and Dark appearance, AMOLED backgrounds, Android 12+ dynamic
  colors, and Asgard/system fonts. Outfit and Fira Code use explicit weights.
- Friendly device names, such as POCO F7, when Android exposes a marketing name.
- Compact automatic recovery bundles with partition badges and detailed image
  selection when opened.
- Readable installer logs decode `ui_print` into the provider's intended messages;
  retained logs support Readable/Raw modes and full raw export.

## Installation and recovery

- Execute the original AnyKernel installer with the pinned four-ABI BusyBox runtime;
  package scripts and tools are preserved.
- Separate selection, device/recovery review and confirmation before installation.
- Snapshot discovered active-slot and shared recovery partitions before executing
  the installer, and retain explicit success, partial failure and unknown outcomes.
- Manifest-based backup and restore validate device identity, partition targets,
  slot, capacity, image size and SHA-256 before writes, then verify written targets.
- Application-wide operation ownership prevents overlapping flashes, backups and
  restores; durable records preserve interrupted outcomes for review.
- Track installer completion, device restart and user-reported kernel health as
  separate observations.

## Distribution and build

- Signed universal APK for Android 7.0+; version code 1020 and target SDK 37.
- GitHub releases supply APK downloads to the Bolt website.
- Updated README, listing resources, privacy information and emulator screenshots.
- Thor-compatible local/CI release signing and Git-ignored JKS/PKCS#12 credentials.
- Source-built BusyBox with complete corresponding source, pinned dependencies and
  an NDK build recipe included as release assets. A clean rebuild reproduces all
  four shipped runtime binaries; the ARM64 build retains the previous 358 applets.

## Compatibility and known limits

Root and an AnyKernel ZIP intended for the exact device/firmware are required.
Automatic snapshots cannot roll back every change a root installer might make.
Keep off-device backups and a working recovery route. Legacy image folders without
a complete manifest cannot be restored through this workflow.

Raw boot-image flashing, KernelSU LKM installation, KMI acquisition and inactive-slot
OTA preparation are not implemented. Broad device/root-manager compatibility and
physical restore/failure-mode validation remain incomplete; a successful installer
exit or detected restart does not prove kernel health.

The screenshots use clearly labeled emulator recovery/log fixtures. The maintainer
previously reported a successful BakaSU kernel install and reboot on a physical
device; this release preparation does not claim another physical kernel flash.
